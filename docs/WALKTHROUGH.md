# A short walkthrough

Start with `python showcase.py`, then open http://127.0.0.1:8766. No installation, Amazon login or AI key is needed for this path. The data folder is separate from a personal workspace.

1. Choose **Inspect a fan**. Build the brief and open the selected owner reports. North Desk Fan has five fictional reviews; its average rating is a local calculation, not an AI judgment.
2. Expand **Read an example interpretation** in the guide. The example is written for this walkthrough and labelled accordingly. Open its source and compare the claim with the quote. One account cannot establish a typical runtime or failure rate.
3. Choose **Compare the fans**, then **Compare products**. Both products have saved evidence. Collection time and model calls are zero. The result makes the small sample and unanswered questions visible.
4. Save the comparison with its sources. The text export retains evidence and limits while excluding reviewer and account fields.
5. Choose **Ask about battery life** and submit the question. In this offline workspace the app shows related passages, not a fabricated AI conclusion. Ask a count question to see a purely local answer.
6. Expand **How this run worked**. Stages and timings come from the persisted job, not an animation pretending that agents are working.

For an engineering discussion, follow with the architecture diagram and `python -m evaluations.run`. The report includes two retrieval failures. Explain why source checks cannot resolve those language and variant issues on their own.

For a live AI demonstration, start the normal dashboard, choose a stored scope, configure a key and allow sharing for that run. Free endpoint availability is variable. Use fictional data for public recordings and label recorded examples if a live provider is unavailable.
